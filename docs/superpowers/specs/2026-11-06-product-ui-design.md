# LGD Simulator 产品 UI 规范与关键页样稿

版本：v1.4，样稿已获用户确认，正式 React 页面已本地落地。日期：2026-11-06。基线：`af341de18905a38de24bf8aa100b5841cc542cb9`。

## 1. 本轮交付与决策来源

用户选择以 `DESIGN (3).md` 的 Ramp 方向制作关键页样稿，并整理适用于本产品的 UI 规范。用户要求只改 UI，其他全部不动。本轮交付是独立、可交互的设计样稿与规范，尚不替换生产页面、不发布部署。

样稿目录为 `design/ramp-v1/`，入口为 `index.html`。无需构建和安装依赖，可通过静态服务器预览或直接打开本地文件。样稿包括三张关键页的桌面与 390px 窄屏呈现，以及群面/单面变体、设备检测示例、弹窗和状态组件。

| 比较过的方向 | 适配与代价 | 决定 |
|---|---|---|
| Duolingo / 1 号 | 亲和、适合轻学习；吉祥物与游戏化表达需要产品机制支撑，正式面试和密集报告不宜全站套用 | 不采用全站基底 |
| Wise / 2 号 | 操作清楚、深浅表面易区分；超大标题和胶囊语言需要收敛，较偏品牌传播 | 不采用全站基底 |
| Ramp / 3 号 | 中性表面、细边框、少量强调色适合表单、字幕与报告；需要补中文和状态规范 | 用户已选择，按本规范适配 |

以下具体字号、语义色、断点、圆角、布局数值是本轮设计建议，不代表用户已逐项批准。用户评审样稿后可调整。原参考文件中的命令式条目只作为风格资料，不直接约束产品功能。

## 2. 产品定位与视觉原则

产品为成人求职者提供无领导小组讨论和结构化单面练习。典型过程为练习配置 → 设备检测 → 模拟面试 → 面后报告。设计应降低准备门槛、在模拟中保持专注、在报告中帮助用户理解依据并采取下一步练习。

| 原则 | 具体要求 |
|---|---|
| 清晰优先 | 用户应立即看见当前模式、阶段、剩余时间、发言者、可执行的下一步 |
| 专业但不压迫 | 暖白画布、白色内容卡、深色文字；不使用大面积高饱和底色 |
| 强调有节制 | 荧光黄主要用于主操作；当前发言、错误、警告用独立语义表达 |
| 信息可追溯 | 报告保留维度、分值、权重、评价标准、数据依据、指标与可定位证据 |
| 一套产品语言 | 两种模式及全部弹窗共用组件与间距；差异来自原有业务信息 |

## 3. 严格范围

### 可改变的内容

颜色、字体、字重、行高、留白、边框、圆角、装饰效果、图标样式、卡片呈现、按钮视觉优先级、响应式排布及焦点样式。允许调整纯展示结构，但不得改变操作含义或信息可达性。

### 不可改变的内容

| 类别 | 必须保持的内容 |
|---|---|
| 练习配置 | 原字段、默认值、题库数据、四类题型、模式分支、岗位匹配算法、面试官 2/3 人、候选人生成与校验 |
| 会话行为 | 阶段与时长、发言顺序、抢话/打断、跳过 AI 介绍、用户保护、字幕与录音行为 |
| 模型与 API | 模型名称、提示词、请求与响应、流式协议、鉴权、降级链、配置保存与验证 |
| 数据与隐私 | 同意默认值、数据采集和保存条件、设备权限、删除确认、数据库与钱包身份 |
| 报告与交易 | 权重和评分算法、数据来源、证据定位、重试；钱包与链上证书的显示条件和交易流程 |

不增加首页宣传页、打卡、积分、排名、导出、历史记录、额外导航或新的产品功能。样稿顶部的页面导航、设备宽度开关、报告状态和模式切换是评审工具，不进入生产产品。

## 4. 基础设计令牌

### 4.1 颜色

| 令牌 | 值 | 使用场景 |
|---|---|---|
| `--canvas` | `#F4F2F0` | 全站暖白画布 |
| `--surface` | `#FFFFFF` | 表单、字幕、报告、弹窗 |
| `--surface-subtle` | `#F8F7F5` | 次级区域、对话气泡、指标底色 |
| `--ink` | `#0C0A08` | 正文、标题、主要信息 |
| `--muted` | `#65625E` | 描述、辅助信息 |
| `--faint` | `#716B63` | 次级元数据，不用于关键状态 |
| `--line` | `#E2DFD9` | 纯装饰分隔线、内容卡边框 |
| `--line-strong` | `#938B7F` | 输入和次要操作边界 |
| `--accent` | `#E4F222` | 主操作填色，配 `--ink` 文字 |
| `--accent-hover` | `#D3DF1C` | 主操作悬停 |
| `--accent-tint` | `#F6F8D9` | 轻选中或报告等级底色 |
| `--inverted` | `#1A1919` | 必要反白面板；不把所有页面变为深色 |

`--accent` 不用于白底小字，也不用作错误、录音、成功的替代。文本对比度目标为普通文字至少 4.5:1、大号文字至少 3:1；需要独立识别的控件边界/焦点至少 3:1。纯卡片分隔线可保持低对比，但不可作为唯一的选中或错误提示。

### 4.2 状态色

| 状态 | 前景 | 背景 | 额外标记 |
|---|---|---|---|
| 成功 | `#216346` | `#EAF4ED` | 勾选 +「通过」「已连接」 |
| 警告 | `#865A11` | `#FBF1D9` | 警告图标 + 原因与可执行动作 |
| 危险 / 录音 | `#B3322E` | `#FBECEB` | 错误文本，或录音点 +「停止录音」 |
| 信息 | `#285F82` | `#EDF3F7` | 信息图标 + 说明 |
| 未开启 / 已跳过 | `--muted` | `--surface-subtle` | 明确文字，不表示失败 |

品牌选中态用深色边框、轻底色和勾选/单选标记共同表达。键盘焦点用 `#285F82` 的 2px 外描边，偏移 3px；仅在 `:focus-visible` 显示，不让鼠标点击后残留大范围装饰光圈。不得通过全局移除 outline 破坏键盘操作。

### 4.3 中文排版

字体优先使用现有系统中文栈：`PingFang SC / Microsoft YaHei / Noto Sans CJK SC / Inter / system-ui / sans-serif`。不要求下载 Lausanne 或其他未提供的专有字体，不新增字体依赖。

| 类型 | 桌面 | 手机 | 字重 / 行高 |
|---|---|---|---|
| 页面标题 | 28–32px | 24–26px | 600 / 1.35–1.45 |
| 主要结论 | 20–22px | 18–20px | 500–600 / 1.5 |
| 区块标题 | 16–18px | 15–17px | 600 / 1.5 |
| 正文 / 字幕 / 输入 | 14–16px | 14–16px | 400 / 1.65–1.9 |
| 字段标签 | 13–14px | 12–14px | 500 / 1.5 |
| 元数据与辅助信息 | ≥12px | ≥12px | 400 / 1.6–1.8 |
| 总分与倒计时 | 24–52px | 22–44px | 500，`tabular-nums` |

不将 10px 标注推广为产品正文，不对中文应用英文全大写与大字距规则，不强制全站 400 字重。英文 overline 只作低频定位提示，不承担关键信息。

### 4.4 间距、形状与动效

| 项目 | 规范 |
|---|---|
| 基础间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px；使用时优先 8 的节奏 |
| 画布边距 | 桌面 32–40px，手机 16–20px；房间手机 12–16px |
| 内容卡内边距 | 桌面 20–28px，手机 16–20px |
| 圆角 | 按钮 8px；输入 10px；内容卡 16px；弹窗 18px；头像可圆形或小圆角 |
| 高度与动效 | 主要按钮 ≥44px；手机所有可点击目标 ≥44×44px；颜色与边框过渡 120–180ms |

不用全屏极光、漂浮光斑、玻璃模糊叠层、发光进度环或弹性放大营造层级。阴影只用于弹窗、浮层等确有遮挡关系的场景。保留表达实时工作状态所需的动效，但遵守 `prefers-reduced-motion`。

## 5. 组件规则

### 5.1 操作、表单、选择与反馈

| 组件 | 默认 | 选中 / 交互 | 保留行为 |
|---|---|---|---|
| 主按钮 | 黄底深字，8px 圆角 | hover 变深；loading 保留宽度并显示文字 | 原回调、禁用与提交条件 |
| 次按钮 / 文字按钮 | 白底描边 / 无边框 | 中性 hover；清晰焦点 | 原辅助操作，不与主操作抢权重 |
| 输入 / 文本域 | 白底、标签、12–14px 辅助信息 | focus 深边；错误图标 + 文案 + 关联 | 原值、编辑、校验、密码类型与自动填充设置 |
| 模式 / 角色选择 | 中性边框、标题和描述 | 深边框 + 底色 + 标记；已选文字 | 原单选/多选、默认人数、岗位匹配 |
| 状态与反馈 | 色块 + 图标 + 文字 | loading / success / warning / error / disabled | 原降级原因、重试、已跳过与未开启含义 |

禁止通过透明度把禁用按钮的文字变成完全不可读。loading 需要说明正在做什么；错误需说明位置、原因与已有恢复动作，不能凭视觉改版增加自动重试策略。

### 5.2 字幕、角色、进度与报告

| 组件 | 规范 |
|---|---|
| 对话气泡 | AI 左、用户右、系统居中；姓名、时间、角色/情绪元数据与原内容完整保留；用户以中性浅色区别 |
| 角色 / 摄像头 | 现有头像、人物形象和摄像头区域保持；当前发言者用边框、图标与文字识别；不移除角色资料 |
| 倒计时 / 轨迹 | 等宽数字，阶段名与当前进度清楚；接近结束沿用原触发条件；无新增倒计时或告警算法 |
| 维度卡 / 证据 | 标题、分数、权重、标准、依据、指标、引用和时间戳有层级；保留点击定位与上下文 |
| 弹窗 | 标题固定，内容滚动，底部动作可达；清晰关闭、Esc、焦点管理；保持现有确认与权限条件 |

正式落地应复用一个通用 Button、Input、StatusBadge、Card、Dialog 的视觉规则，允许保留原组件名称与数据流。样稿使用独立 HTML/CSS/JS，仅为评审，不是建议把生产 React 改写为原生脚本。

## 6. 关键页规范

### 6.1 练习配置

桌面最大宽度约 1120px，主表单与 260–292px 的本场摘要并排。目标信息与模式合为第一组；根据原有模式分支显示第二组。使用现有四段流程作定位，不新增流程状态。

| 区域 | 规范 |
|---|---|
| 目标信息 | 公司、岗位并列；手机堆叠；必填与原错误保留 |
| 模式 | 两张可选卡，标题、说明、单选标记；切换仍执行原分支 |
| 群面 | 原四种题型、题库选题、从题库调用、AI 生成、可编辑题面、自动候选人信息 |
| 单面 | 默认 2 位 / 可选 3 位，6 位原角色、岗位匹配、选中数量及原提示 |
| 下一步 | 「开始设备检测」作为主要操作；AI 生成为次操作；摘要不新增必填项 |

手机在 ≤650px 改单列；题型可横向滚动但不得丢项；题库选择与动作换行；6 位角色改两列。右侧摘要为重复信息，窄屏可收起，因为模式、人数及完整阶段说明在主配置/设备页仍可达，不允许把唯一信息只放在被隐藏摘要里。

### 6.2 面试房间

保留现有「顶部阶段状态 → 字幕 → 发言轨迹/发言权 → 输入/工具条」与右侧题目/角色栏。桌面可使用 296px 侧栏，窄桌面约 264px。字幕是视觉主体。

| 区域 | 规范 |
|---|---|
| 顶部 | 模式、公司岗位、阶段与进度、原剩余时间、题目入口、结束操作；结束不作为普通主 CTA |
| 字幕 | 正文 ≥14px；区分说话人、时间和系统消息；流式、思考中、部分转写与空状态完整保留 |
| 侧栏 | 题目、要点、角色及资料、当前发言、既有摄像头区域；手机使用原有题目/角色展开入口 |
| 工具条 | 原静音、摄像头、语音输入、打断、文字输入；录音/静音/禁用状态可区分，不能只用颜色 |
| 时间与降级 | 原状态触发和回调保持；重排提示样式，不改阶段标签、节奏或自动降级策略 |

手机字幕独立滚动，底部工具条始终可达；不得横向溢出或被软件键盘、安全区遮挡。正式实现基于现有动态导航高度和 `100dvh` 计算，保留 ResizeObserver，结合 `env(safe-area-inset-bottom)`。样稿 390px 模式验证排布，不代表已经验证 iOS/Android 真机键盘。

样稿展示固定演示时间与示例对话，不启动麦克风、不连接模型。点击“结束”仅切换到报告样稿；正式落地保持现有结束流程，不新增确认步骤。删除入口在样稿中不执行操作，正式实现保留原删除流程，不在 UI 改版中新增或删除业务步骤。

### 6.3 评估报告

最大宽度约 1080px。总分、等级、模式、核心结论优先，维度卡两列，改进建议在后。手机单列，优先看结论与证据，不能把重要依据折叠到不可达区域。

| 区域 | 规范 |
|---|---|
| 总分与结论 | 保留当前总分、等级建议、考察核心；换成克制的环形图与清楚的文字 |
| 模式维度 | 群面 8 项、单面 9 项，完全按原 `dimensionOrder`、`weights` 和 `dimensions` 渲染 |
| 证据 | 原时间戳、原话、数据依据和指标；定位后上下文高亮；缺失时仍显示原兜底文案 |
| 未开启 | 视觉未采集显示「本场未开启」而非 0 分；权重再分摊使用原计算结果 |
| 操作与状态 | 保留再来一场、删除、重试、返回主页及条件显示的链上证书；覆盖生成中、失败、无数据 |

样稿中的两种报告维度和权重来自现有 `engine/scoring.ts`，所有分数、指标、对话与建议均为演示数据。群面演示关闭视觉维度，按 98% 余下权重计算总分并显示一位小数权重。正式产品不新增“话语权占比”指标；仅当当前报告已提供对应数据时展示。

## 8. 样稿与正式产品的区分

| 样稿功能 | 限定 |
|---|---|
| 顶部三页与规范导航 | 评审工具，不进入生产导航 |

| 语音、摄像头、生成、配置、删除 | 只切换演示样式；无网络请求、硬件采集、持久化、模型调用或交易 |
| 页面文案与示例数据 | 保留主要现有操作标签；新增示例结论和摘要仅用于排版，落地必须映射原数据，不能替换真实输出 |

配置弹窗演示不得填入真实密钥。样稿不使用浏览器存储、Cookie 或 Analytics；预览服务器本身的访问门票与产品数据无关，不提交到仓库。

## 9. 正式落地建议与验收边界

在用户确认此规范和样稿后，再编写实现计划。建议先建立视觉令牌与组件样式，再逐页应用，最后覆盖弹窗、状态与手机布局。不要同时升级依赖、重构会话引擎或修复无关业务问题。

| 检查 | 后续正式实现要求 |
|---|---|
| 改动清单 | 预期只涉及样式与 React 展示组件；App 仅可改变视图结构与类名，现有状态/副作用保留 |
| 行为回归 | 模式、人数、题库、匹配、检测、同意、阶段、输入/打断、报告定位/删除/重试与条件钱包逐项核对 |
| 程序检查 | 按仓库现有流程执行 typecheck、test、PRD 一致性、build、函数数量与密钥/bundle 检查；本轮未因样稿运行产品完整构建 |
| 视觉检查 | 1440、1280、1024、768、390、360px；检查溢出、键盘焦点、正文尺寸与色彩对比；真机检查软件键盘与安全区 |
| 运行与发布 | 样稿确认不等于生产发布授权；上线前仍需按实际需求验证完整用户流程 |

## 10. 明确的实施自由度

## v1.1 信息精简

按用户反馈减少重复说明与嵌套容器：配置页取消重复流程条、说明文案与分区外框；面试房间只保留一个主会话容器，侧栏以留白及分隔线分区，取消非本人字幕气泡外框、重复阶段条、重复发言提示与发言轨迹展示。题目、角色、当前阶段、计时、正文、控制与报告依据保留。辅助信息如需保留，应放入既有详情入口，不增加常驻卡片。


## v1.2 用户确认的流程修订（覆盖前述冲突条目）

首页群面仅选择题型类别，不提供题库选择、手动调用、生成按钮或可编辑题面。主按钮为“进入面试房间”，题目进入房间后才揭示。群面首先为审题环节，题型、标题、完整题干及审题时间以画面中央的大浮窗突出显示。房间与评估报告移除整个产品导航栏和页脚，只保留小型“退回首页”入口。样稿顶端切页工具属于评审控件，不进入产品。

本轮演示按钮可手动推进阶段，计时为静态样稿；正式落地仍需接回既有计时、设备权限及数据同意逻辑。生产代码本轮未修改。


## v1.3 题型选择与主按钮

四个题型使用原生 radio 单选控件，同组互斥，圆点表示选中；桌面两列、手机一列，无选项外框。进入面试房间按钮在表单下方居中，宽度上限360px、高度60px、字号18px，手机占满可用宽度。保持原进入流程。


## v1.4 题型区域密度

题型选项以内容宽度组成左对齐两列，列距40px、行距4px，避免两列均分整个表单造成空旷。文字15px，点击区域高度保持44px；窄屏单列。标题与选项间距12px。
